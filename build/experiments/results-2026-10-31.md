# ECS XZ block reuse — 2026-10-31

Full-size test using the completed Amiga-ECS and PiStormECS releases on the
Backup output drive. The normal build path was not changed. The prototype
uses four workers and the existing preset-1, 3 MiB-block Amiga-ECS archive.

| Measurement | Result |
| --- | ---: |
| HDF size | 15,799,762,944 bytes |
| Blocks reused | 5,021 / 5,023 (99.96%) |
| Blocks recompressed | 2 (6 MiB) |
| Assembly, including source decoding/comparison | 98.38 s |
| Independent full-output xz verification | 61.69 s |
| Total reuse + verification | **160.07 s (2m40s)** |
| Prior streaming compression + verification | 531.40 s (8m51s) |
| Observed reduction | **371.33 s (6m11s), 69.9%** |
| Prototype compressed size | 5,088,386,712 bytes |
| Existing PiStormECS compressed size | 5,088,284,832 bytes |
| Size increase | 101,880 bytes (about 100 KiB) |

The boot prefix was 68,157,440 bytes and partition padding 180,224 bytes.
The complete decoded image was 15,868,100,608 bytes, with SHA-256:

```text
cea24058d22a4000af7ed317f488e6e425852e5e9fedc060b40aeb54ffeb7c7d
```

The expected image bytes came from decoding the existing PiStormECS release
into prefix, private patched HDF, and zero padding. This one-time reference
extraction took 133.83 seconds and is excluded from the prototype timing:
production PiStorm builds already have the private patched HDF and prefix.
The seed archive is likewise already produced by the Amiga-ECS packaging step.

This is one experiment, not a controlled end-to-end build benchmark. Reference
extraction immediately preceded it, so filesystem caches may be warmer than
in a normal run. The comparison uses historical timings from the same output
drive; intervening load and filesystem conditions can differ. AGA and RPi
reuse have not been benchmarked. Do not extrapolate this reduction to the
entire distro run.

Five tests cover exact packed-byte preservation, patched blocks, image layout,
independent decoding, rejection of corrupt/unsupported inputs, input changes,
verification failure, and preservation of an existing release on failure.
The output remains one standard CRC64 XZ stream. No Makefile, production
packager, existing release, or source HDF was modified by this experiment.

A second full-image decode using **7-Zip** independently produced the same
15,868,100,608 bytes and SHA-256. That additional compatibility check took
165.35 seconds and is excluded from the 160.07-second prototype total; the
proposed production path retains the existing xz verification, not two full
verification passes. Small-fixture tests also decode with Python's lzma.

## Integrated targeted run, 21:08–21:35

The integrated hash-manifest implementation completed successfully with
`DISTRO_PACKAGES=pi,pistorm-aga` on the Backup output drive. The main HDF stayed
stable. No fallbacks or package failures occurred; both reused images passed
full decompression, byte-count, and SHA-256 verification. Neither consumer
decoded the seed archive.

The whole selected run, including Amiga seed creation and checksums, took
27m38s. Seed compression with block hashes took 429.1 seconds (7m09s), and the
complete Amiga package took 7m34s. The earlier clean run's seed compression
took 925.6 seconds. Both use preset 1; do not attribute that additional seed
speedup to reuse. Machine load, caches, and run ordering differ, and this is
not a controlled whole-suite benchmark.

Compared with that prior run, RPi grew from 10,163,874,132 to 10,169,186,540
compressed bytes (+5.31 MB, 0.052%). PiStorm AGA grew from 8,806,927,216 to
8,813,013,052 bytes (+6.09 MB, 0.069%). Source boot-time writes and generated
image metadata also differ, so these are observed size changes, not isolated
compression-format overhead.

The remaining preparation costs include RPi blank unpacking (150 s) and HDF
copying (308 s), plus PiStorm private-copy/overlay installation (153.8 s).
These now account for substantial portions of their package totals.
