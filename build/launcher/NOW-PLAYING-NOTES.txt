At successful playback startup, the music process publishes the MOD path.

Now Playing: , centers using actual TextLength/font metrics, blanks the full
footer width with a fixed black pen and renders using the fixed text pen.
Long names are clipped to the available width. No image rescaling involved.

The footer is captured before drawing and restored after 250 DOS DateStamp
50-Hz ticks (5 seconds, including NTSC). A new track refreshes the notification
and timer. A private cloned RastPort leaves menu/helper drawing settings alone.
Navigation continues during the overlay. Exit/exception cleanup drains blits and
restores/frees the strip. Allocation failure skips the overlay without blocking
playback. The producer never draws and never sleeps on behalf of the overlay.

Binary hook details (runtime offsets; file code begins at byte 32):
 $8344: producer runs after native PT playback/volume setup, verifies module
 object at music-context+50, publishes bounded filename, then replays
 moveq #-1,d0 / movea.l d6,a0 before native playing flag write at $8348.
 $4bee: replay menu WaitTOF and poll produced/consumed sequence numbers.
 $5656: normal menu selection exit restores/frees footer and replays native
 return-value/stack adjustment.
 $90e6: common main cleanup catches exceptions as well, before fonts/windows
 are released; replays the native exception-frame pop.

Producer/menu snapshots are protected with short task-context Forbid/Permit;
no DOS/graphics calls are made while forbidden. There is no new interrupt,
message port, timer.device request, task or persistent Chip allocation.
RastPort clone is 100 bytes; saved BitMap supports 1..8 planar bitplanes,
byte stride <=128, footer height <=64 and native screen height. Unsupported
geometry skips display. UI black/text pens are (1<<depth)-2 and -1.
Current dimensions use full 640px width and font height+4 at screen bottom.
The capture descriptor uses native stride, per-plane allocation and ByteRun1
image handling is entirely unrelated to this overlay.

Revision AVSNOW03 — shuffled playlist:
The music process retains native directory scanning, RNG seeding, loading,
playback, end-of-song signals, F8/Space pause and F9 next-track handling.
Immediately after scanning and RNG seeding, it creates a temporary 4*N-byte
MEMF_PUBLIC pointer array, Fisher-Yates shuffles it using native Rand(i+1),
and relinks the existing E filename strings in that order. The array is freed
immediately; no extra Chip RAM or persistent pointer array is required.
Every selection advances a cursor through the linked list and wraps to its
head. The permutation is reused at wrap, so every loadable track is selected
once per cycle. The order is generated anew on launcher/music-process startup.
The old per-track random choice and last_mod_index exclusion are bypassed;
last_mod_index is still written as playlist ordinal for native bookkeeping.
If the temporary allocation fails, or there are more than 65535 entries,
a sequential cycle covers every entry instead. Zero/one-entry lists are safe.
No new directories, configuration files or prebuilt playlist file are needed.

Runtime hooks: $8124 follows the existing RNG seed and initializes/shuffles
once; $8186 preserves the native already-playing guard, selects the next item
and advances only when a new module is needed. String linkage is at path-8;
native head frame offset -60, tail -20, count -88, ordinal -36. State+56 is
cursor; state+60 is next ordinal. Original strings and their owners are retained.
Patch remains last in chain and upgrades AVSNOW01/02 by restoring baseline first.
